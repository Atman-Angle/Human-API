# 圈子（聚合帖）与求证：前端信息架构

## 两条产品线必须分开

| | 圈子 / 聚合帖 | 求证 |
| --- | --- | --- |
| 入口 | 顶部圈子 tab：AI、科技、编程、教育、职场、数码 | 顶部「求证」、帖子详情页的「知识边界」 |
| Agent 做什么 | 检索该圈子在知乎的讨论 → 合并重复提问 → 重新生成标题清晰、结构化的帖子 | 划定已有证据与知识边界 → 指出还缺什么、需要谁来补 |
| 用户做什么 | 阅读帖子、看来源与引用 | 用第一手经历补齐 Evidence Gap（问卷式） |
| 数据 | 聚合帖：来源讨论数、话题、引用回答、知识边界 | Investigation / Knowledge Object：Claim、Gap、Mission、Knowledge State |

「推荐」是**各圈子聚合帖的混排**，不是求证列表。
圈子页**不出求证卡片**；求证只出现在「求证」入口和帖子详情页的转化按钮上。

## 页面与路由

| 路由 | 内容 |
| --- | --- |
| `/` | 推荐：各圈子聚合帖 + 「正在进行的求证」区块（最多 2 条，可跳转） |
| `/?circle=ai` | 圈子页：圈子头（Agent 检索规模、重新检索并整合）+ 该圈子聚合帖 |
| `/?circle=more` | 圈子广场：全部圈子入口 |
| `/post/[id]` | 聚合帖详情：关键结论、整合自哪些讨论、引用回答节选、知识边界 → 「对这个问题发起求证」 |
| `/#verify` | 求证列表：Knowledge State + Evidence Gap |
| `/#search` | 发起求证（composer） |
| `/#mine` | 我的求证控制台 |
| `/investigation/[id]` | 求证详情：知识边界、社区贡献、Mission、第一手经历提交 |

## 交互约定

- 圈子 tab 切换会同步 URL（`?circle=`），刷新和分享都能回到同一个圈子。
- 「重新检索并整合」= Agent 重新跑一轮检索与整合（当前为演示态：进度条 + 更新时间）。
- 帖子卡片必须体现「Agent 整合」：来源讨论数、整合自的原始提问、话题标签。
- 求证卡片必须体现「缺口」：Knowledge State、相关讨论数、第一手经历数、当前 Evidence Gap。
- 求证列表**不出现帖子元素**（作者、发布时间、摘要、点赞）：只有问题、当前判断、还缺什么、需要谁来回答、贡献入口。
- 推荐页只放 6 条聚合帖，下面接「正在进行的求证」，避免求证被淹没。

## 数据兜底

后端没有公开求证或未连接时，帖子与求证都退回 Mock 演示数据，并在页面上标注「演示数据」，
保证 Demo 任何时候都不是空白页。
